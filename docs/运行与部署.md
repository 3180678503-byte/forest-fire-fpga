# 运行与部署

## 现有演示设备

设备已安装当前工程时，仍用电脑正式页面http://127.0.0.1:8770。选择实时相机＋HDMI、所需Qwen模式，保存并启动。网页显示程序状态与性能；视频从HDMI输出。

接线：AN5641接J16；HDMI接显示器或已验证图传设备。CH340 TXD→ESP D16、RXD→D17、GND共地，转串口电源脚不接。ESP使用可靠USB供电。通信USB由服务自动识别。

外设型号、完整接线、AT固件、串口参数和网络检查见[ESP32外设与接线说明](ESP32外设与接线说明.md)。

## 拷贝板端运行目录

`02_board_app/runtime/`包含板端运行程序、模型、配置和依赖。停止已有视觉任务后，将该目录部署到/home/work/forest_fire_fpga/board等目标路径。当前演示设备使用/home/work/an5641_full_action_20261031/board。

首次安装动作依赖后，可直接测试本地相机＋HDMI：

```bash
cd /home/work/forest_fire_fpga/board
python3 action/install_deps.py
python3 -u run_system.py --input live --output hdmi --qwen-off --duration 30
```

固定图片路径用于相机无关的NPU检查：

```bash
python3 -u run_system.py --input offline --image fixtures/wire_input.jpg \
  --qwen-off --duration 20
```

应用部署依赖板端已有的Linux根文件系统、设备映射、驱动和iCraft运行库，SD卡系统镜像需另行准备。04_firmware/BOOT.bin用于匹配的目标硬件；普通应用更新按运行目录部署。

## PC和ESP控制

03_control/source包含完整PC服务器和板端守护，source/host及source/common提供复核依赖。`03_control/scripts/`、`deploy/`保留当前安装工具和systemd文件，其历史绝对路径见original_path说明，移植时以实际部署目录修改。

使用本包新增PC入口：

1. 复制03_control/config.example.json到包外私有目录，如pc.json；填写设备、Wi-Fi和双方一致的认证key。新入口自动将host_project设为本包03_control。
2. PC联网并启用与板端配置一致的热点。新入口使用电脑已启用的热点。
3. 执行`python 03_control/start_control.py --config /private/pc.json --mode mock`。真实复核改为`--mode auto --allow-live-upload`，通过环境变量QWEN_API_KEY或私有cloud_key_file配置云密钥。
4. 板端服务配置的runtime、host、device、认证key及Wi-Fi信息与PC对应；使用03_control/source/board_daemon.py与deploy中的systemd文件。当前安装路径为/home/work/esp32_remote_control_20261028。

认证配置模板中的performance_telemetry参数按当前守护默认配置核对；默认值由源码控制，模板未覆盖的项沿用默认行为。部署新服务时使用完整source目录；package内的control_source作为当前运行包快照保留。

正式页面是8770，8771历史开发预览使用合成数据。相机ROI、云回复与板端回执按同一会话/请求关联；真实服务模式产生云调用。

结束时使用网页停止；日志位于板端outputs/<session>/。动作当前为ACTION SIM，飞行由飞手操控。

## 常见检查

- 相机初始化报IIC NACK：当前系统曾在重新插紧排线并重启后恢复。正常关机断电后核对J16连接、卡扣和供电，再读芯片ID0x5640。
- 有线SSH：板端当前192.168.126.49/24，电脑直连网卡在同网段；ESP热点地址与板端SSH地址分别识别。
- 同时只运行一个占用相机/NPU/HDMI的任务；启动前查询现有进程或网页状态。
- 页面NPU独立耗时/采集耗时仍显示待测，已有FPS字段为软件处理吞吐。
