2026-10-27。适用当前AN5641/J16、1080p30、candidate_v2网口演示工程。本次核对本机目录、XPR、源码引用和既有构建报告，未启动Vivado GUI、未重新综合、未连接开发板。

## 1. 先选对工程

当前演示分支：`D:/Project/drone_project/camera/an5641_eth_psfifo_20261024`。

Vivado工程入口：

`D:/Project/drone_project/camera/an5641_eth_psfifo_20261024/hw/ps_in/ps_in.xpr`

## 3. 用Vivado 2018.3打开

本机已安装：`D:/Vivado/2018.3/bin/vivado.bat`。当前PATH中的vivado则指向2023.1，所以首次查看请明确选择2018.3。

1. 启动Vivado 2018.3。
2. 欢迎页选择 **Open Project**。
3. 选择上述`hw/ps_in/ps_in.xpr`。
4. 等待Sources加载，确认顶层为 **ai7030_top**。

也可以在Windows PowerShell执行下面一行，直接用指定版本打开该工程：

```powershell
& "D:\Vivado\2018.3\bin\vivado.bat" "D:\Project\drone_project\camera\an5641_eth_psfifo_20261024\hw\ps_in\ps_in.xpr"
```

查看源码、BD和既有结果不需要连接开发板。首次阅读保留现有IP版本；如果误用新版打开并提示升级工程/IP，退出后改用2018.3。

## 4. 在界面中看什么

### 看顶层代码与模块关系

在 **Sources → Hierarchy → Design Sources** 展开`ai7030_top`。双击文件/模块可查看源码；在Source File Properties中查看文件实际路径。

顶层文件：`hw/ps_in/ps_in.srcs/sources_1/rtl/ai7030_top.sv`。本工程`MIPI_AI_INPUT`默认值为1，使用AN5641输入分支；当前启用通路由顶层配置决定；旧SDI与以太网测试代码留作参考。

建议顺序：

| 文件或实例 | 阅读目的 |
|---|---|
| ai7030_top.sv | 整个板级设计的模块实例、时钟、复位和信号连接 |
| u_mipi_capture_axis / mipi_capture_axis.sv | MIPI接收、去马赛克、Gamma及控制寄存器分配 |
| u_an5641_camera / axis_rgb_to_camera.sv | AXI视频流转为原例程使用的RGB/行场信号，并统计帧/行/错误 |
| u_an5641_pixel_clock / an5641_camera_clock.sv | 摄像头后级视频时钟和复位同步 |
| frame_trans_inst0 / display/frame_trans.v | 进入既有AI输入支路的视频处理连接 |
| frame_to_ps_inst0 / display/frame_to_ps_largebuf.v | 送到PS画面缓冲的支路 |
| ps_ai_wrapper_u0 / ps_ai_wrapper.sv | PS/AXI子系统与顶层的连接 |
| ZGolo / AI_Mate_0 | 厂商AI相关IP接口；内部部分可能以封装、网表或加密形式提供 |

### 看Block Design方框图

在Sources中找到并双击`ps_ai.bd`：

`hw/ps_in/ps_in.srcs/sources_1/bd/ps_ai/ps_ai.bd`

该图主要显示PS和AXI互连子系统。摄像头、视频转换和AI接口还在顶层RTL里实例化，所以单看BD看不到整条数据流。

### 看RTL连接示意图

左侧 **Flow Navigator → RTL Analysis → Open Elaborated Design**。加载后选模块，右键 **Schematic**，逐级展开模块和连线。它展示RTL展开后的结构，不等同于完成布局布线的物理电路。某些厂商IP只能展示接口或网表层次。

### 看引脚与时钟约束

在Sources中展开 **Constraints → constrs_1**，重点查看：

- `mipi_csi2.xdc`：MIPI相关约束；
- `ai7030_top.xdc`、`7030_peripheral.xdc`：板级约束；
- 工程根目录`rtl/an5641_reset_cdc.xdc`、`rtl/an5641_input_cdc.xdc`：额外跨时钟/复位约束。

### 看实际交付版本的布局布线

本分支构建脚本在工程外单独完成了最终route，最终检查点为：

`D:/Project/drone_project/camera/an5641_eth_psfifo_20261024/validation/hardware/routed.dcp`

因此`ps_in.runs/impl_2`及GUI的Open Implemented Design不应直接当作最终交付结果。要看最终布局布线，可另开一个空的Vivado 2018.3窗口，在底部Tcl Console执行：

```tcl
open_checkpoint {D:/Project/drone_project/camera/an5641_eth_psfifo_20261024/validation/hardware/routed.dcp}
```

随后看Device、Netlist、Timing和Utilization。现有文本报告可直接打开：`validation/hardware/timing.rpt`、`utilization.rpt`、`drc.rpt`、`route_status.rpt`。

## 5. Vivado与实际运行软件的分工

```text
Vivado中的硬件：
AN5641 → MIPI → 去马赛克/Gamma → 视频适配/裁剪缩放
                              ├→ ImageMake/PLDDR/NPU接口
                              └→ PS画面缓冲

Linux中的软件：
相机寄存器初始化 + iCraft调度 → ARM后处理/画框 → VPU编码 → 网口/电脑
```

以下文件用VS Code查看更直接：

- 网口演示主程序：`source/board/runtime/src/yolov8_plin_eth.cpp`；
- NPU输入/输出调度：`source/board/runtime/include/yolov8_plin_actor.hpp`；
- CPU DFL优化：`source/board/runtime/include/dfl_fused_cpu.hpp`；
- RGB565到NV12：`source/board/runtime/include/rgb565_nv12.hpp`；
- 运行模型与阈值：`board/configs/eth.yaml`；
- 相机初始化：`board/an5641_ctl.py`和`board/profiles/an5641_raw10_1080p30.json`。

模型json/raw是交给iCraft在板上加载的模型工件，不会在Vivado里展开成YOLO网络层图。NPU厂商IP的内部可见性与模型编译图是两件事。

## 6. 固件与工程文件的对应

流程为：Vivado设计/布线 → 原始`.bit` → Procise针对JFMQL30TAI676H转换 → 与FSBL/bl31/U-Boot打包为`firmware/BOOT.bin`。

XPR中Vivado侧part为`xc7z030ffg676-2`；这是现有厂商流程的工程设置，实际目标仍为FMQL30TAI-Lite，不应据此把板卡当成普通Zynq开发板重配。

当前最终原始bit为`validation/hardware/ai7030_top.bit`，转换bit为`firmware/an5641_psfifo128_disable_icap.bit`。文件存在与运行验收是两件事，当前质量/性能边界见reports中的实测报告。

工程引用的两处IP仓库仍位于`camera/an5641_mipi_20261022/hardware/`下的`PS_AI IP/PS_AI IP/processing_system7_v5_5`及`AI_Mate_IP/AI_Mate_IP_repo`，已核对存在。保留这处基础目录，不要只移动单个XPR。初次查看无需运行scripts/build_hardware.tcl，该脚本会重置综合并启动构建。
